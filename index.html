01 · 技术路线

当前完整技术路线

不是把点云特征直接塞给动作头，而是让三维信息先改变视频模型的内部表征，再由动作模型读取这个表征生成动作。

第一步 · 输入仿真器提供的对象级三维真值物体局部点云、4×4 位姿、对象编号、图像边界框、有效标记、夹爪位姿
第二步 · 编码Point-MAE 形状编码 + 位姿编码把物体形状、位置、朝向、相对夹爪关系、身份和可信度变成统一的对象特征
第三步 · 注入按图像位置进行交叉注意力融合依据对象边界框，把对应三维特征送到 Cosmos 视频画面中的相应区域
第四步 · 表征形成加入三维信息的视频隐藏表征在 Cosmos 第 17 层附近得到“看过视频也读过三维信息”的内部特征
第五步 · 监督预测未来三维变化预测第 t+7 帧的平移、旋转、表面点轨迹以及物体与夹爪的关系
第六步 · 动作动作扩散模型生成动作Action DiT 读取加入三维信息的视频表征，生成一段连续机器人动作
研究边界：第一阶段直接使用仿真器提供的对象编号、三维网格、位姿和空间位置真值，暂不处理现实图像中的自动检测、对象匹配与跟踪。当前三维信息注入 Cosmos 内部指定层，但还没有做多层深度注入。

第一步详解：数据是什么，又从哪里来？

LIBERO 是基于 MuJoCo 的机器人操作仿真环境。每条专家示范都记录了任务语言、摄像机画面、机器人状态、专家动作和逐帧仿真状态。我们重放每一帧仿真状态，直接读取物体和夹爪的真实三维状态，再保存成与原始轨迹配套的几何伴随文件。它不是从图片里估计出来的，所以当前阶段没有检测误差。

LIBERO 专家示范例如“拿起牛奶盒并放进篮子”，包含图像和正确动作。
恢复逐帧仿真状态让 MuJoCo 精确回到示范中的每一个时刻。
读取三维真值取得对象网格、点云、位姿、夹爪位姿和对象在画面中的位置。
保存几何伴随文件与原始视频和动作一一对齐，训练时同步读取。

每个对象具体包含什么？

假设一条轨迹有 T 帧、场景有 O 个对象，静态形状每个对象保存一次，位置与朝向则每一帧保存一次。

数据直观含义典型形状在模型中的作用
局部点云从物体三维网格表面采样的点，位于物体自身坐标系；物体移动时它不变。[O, 1024, 3]告诉模型“这个物体长什么样”。
物体位姿4×4 矩阵，包含三维位置和三维朝向；每帧都会变化。[T, O, 4, 4]告诉模型“物体现在在哪里、朝向哪里”。
夹爪末端位姿机械臂夹爪当前的位置与方向。EEF 是“末端执行器”的英文缩写。[T, 4, 4]用于计算物体相对夹爪的距离和方向。
对象编号同一场景中稳定的对象身份编号，不等于点云形状本身。[O]帮助模型区分碗、瓶子、篮子等实体，同时需要消融以防模型只记编号。
图像边界框物体在摄像机画面中的矩形区域，由左上角和右下角坐标表示。[T, O, 4]把某个物体的三维特征送到视频中该物体所在区域。
有效标记该对象槽位是否真的存在；补齐出来的空槽位标为无效。[O]避免模型关注不存在的对象。
任务目标标记指出当前任务重点操作的是哪个对象。[O]用于选择未来预测对象和构造“错误位姿”等对照条件；它不直接加进对象特征。
可信度这条三维信息有多可靠；当前来自仿真真值，通常很高。[O]为将来接入有噪声的真实检测器预留可靠性权重。

“位姿分支”到底是什么？

位姿就是“位置 + 朝向”。位姿分支不是另一套大模型，而是编码器中专门处理 4×4 位姿矩阵的一条小型网络路径。

它同时读取物体的绝对位姿、夹爪位姿和“物体相对夹爪”的位姿。例如它能表达“瓶子在夹爪前方 8 厘米、左侧 2 厘米，瓶口向右旋转”。这类信息比单纯知道瓶子形状更直接地决定机器人下一步往哪儿移动。

图像边界框是什么？

图像边界框（bbox）就是框住物体的矩形，用 [左、上、右、下] 四个数表示。它只说明物体出现在画面的哪里，不描述物体的精确三维形状，也不等于逐像素分割轮廓。

当前边界框由仿真器真值计算，不是检测器猜出来的。它用于让“碗的三维特征”主要影响画面中碗所在的视频小块，而不是平均影响整个画面。

这里的几种“标记”不要混淆

有效标记：这个对象槽位是否存在；任务目标标记：它是否是当前要操作的对象；像素分割掩码：图像中哪些像素属于该对象。

当前空间注入主要使用图像边界框做区域路由。有效标记用于屏蔽空对象，任务目标标记用于选择监督对象和构造对照实验；它们并不等于稠密的逐像素分割图。

Point-MAE 负责什么？

Point-MAE 是预训练点云编码器。它把每个对象的局部点云分成若干局部区域，再编码成形状特征，从中表示边缘、平面、开口、长宽比例等三维结构。

当前先冻结它，保留预训练形状知识，也避免用少量 LIBERO 数据把它训坏。它负责“长什么样”，位姿分支负责“在哪里、朝哪里”。

最终融合了哪些信息？

真正相加形成对象特征的是五类信息：① Point-MAE 提取的形状特征；② 物体在共享坐标系中的位置和朝向；③ 物体相对夹爪的位置和朝向；④ 对象身份编号；⑤ 信息可信度。它们先映射到相同特征维度，再逐项相加并归一化。夹爪自身位姿还会形成额外的上下文特征。

对象有效标记不作为数值特征相加，而是在注意力中屏蔽空槽位；任务目标标记也不直接进入对象特征，它主要用于指定未来预测对象和构造受控实验。

随后利用图像边界框，把对象级几何特征送到 Cosmos 中对应的空间视频特征。这样得到的视频隐藏表征既包含“画面看到了什么”，也包含“物体三维形状、真实位置以及它与夹爪的关系”。Action DiT 最终读取的是这个增强后的视频表征，而不是绕过视频模块直接读取原始点云。

用“夹取牛奶盒”举一个完整例子

Point-MAE 告诉模型：这是一个细长盒状物体；位姿分支告诉模型：它在夹爪前方 7 厘米、左侧 2 厘米；图像边界框告诉模型：它位于画面右下区域；对象编号用于区分这个实体，任务目标标记则用于选定需要预测和扰动的目标对象。

这些信息先改变牛奶盒对应区域的视频内部特征。训练时再要求这个特征能够预测第 t+7 帧牛奶盒移动了多少、表面点去了哪里以及它与夹爪的关系如何变化。第 t+7 帧的真实位姿只作为训练答案，不会作为当前输入，因此不存在偷看未来信息。

02

把不同类型的三维数据编码成统一的对象特征

这一环节解决的问题是：点云、4×4 矩阵、对象编号都是完全不同的数据格式，必须先转成 Cosmos 能够使用的同维度特征。

输入

每个对象的 1024 个局部三维点、当前物体位姿、夹爪位姿、对象编号、可信度和有效标记。

内部处理

形状、位姿、身份和可信度分别编码，再映射到与视频隐藏特征相同的维度并相加融合。

输出

每个对象得到固定数量的“对象几何特征”；一批对象组成可被视频特征查询的几何特征序列。

局部点云→归一化与局部点块→冻结 Point-MAE→可学习查询向量汇总→形状特征
物体 4×4 位姿+物体相对夹爪位姿→小型位姿网络→位姿特征
形状特征+位姿特征+对象编号特征+可信度特征→归一化后的对象几何特征

为什么点云要先归一化？

Point-MAE 预训练时更擅长观察以物体自身为中心的形状。代码会把局部点云变换到适合 Point-MAE 的尺度，同时另外编码物体真实尺寸，避免归一化后丢失“这个物体究竟有多大”。

为什么平移量要放大？

位姿矩阵中的旋转数值通常在 −1 到 1，位置按米记录时可能只有 0.01～0.5。当前把平移部分按比例放大后再送入小型网络，避免厘米级位置变化在数值上被旋转分量淹没。

为什么使用预训练 Point-MAE？

它已经在大量点云上学习过局部形状结构，比从少量 LIBERO 数据重新训练一个点云编码器更稳。当前冻结它，只训练后面的汇总、投影和融合部分。

有效标记怎么使用？

不同场景对象数量不同，批处理时需要补齐空槽位。有效标记会把这些空槽位对应的几何特征从注意力中屏蔽，而不是把“无效”当成一种物体特征。

这一环节的目的：得到既表达物体形状，又表达真实位置、朝向和夹爪关系的对象级特征。它不是最终动作，也还没有改变视频，只是为下一步注入做好准备。
03

根据图像边界框，把对象特征注入正确的视频区域

这一环节解决“哪个三维对象应该影响画面中的哪一块”。如果没有空间路由，碗的三维信息可能同时干扰桌面、机器人和背景。

输入

Cosmos 某一层的时空视频特征、对象几何特征，以及每个对象在当前画面中的图像边界框。

内部处理

把图像边界框换算到 Cosmos 的特征网格，建立“每个视频小块允许读取哪些对象”的布尔路由表。

输出

形状不变但内容被三维信息修正的视频特征；每个视频位置只重点读取与自己空间对应的对象。

图像中的对象矩形框→映射到视频特征网格→生成空间路由表→视频位置查询对应对象特征→残差加回视频特征

交叉注意力是谁查询谁？

视频特征是“查询”，对象几何特征是“键和值”。直观地说，每个视频小块会问：“与我这个图像位置相关的对象三维信息是什么？”然后把读到的信息用于修正自身。

边界框如何限制读取范围？

当前观测帧中，只有位于某个对象边界框内的视频小块可以读取该对象特征。夹爪位姿属于全局机器人上下文，可覆盖当前相机视图。对于尚不知道物体会移动到哪里的未来位置，路由限制会适当放宽。

为什么使用残差方式？

模型不是丢掉原视频特征重新生成，而是计算一份“三维修正量”，再加回原特征。这能保留 Cosmos 原有的视频知识，同时只补充缺少的几何信息。

什么叫零初始化？

残差输出层初始权重设为零。因此刚接入模块时，三维修正量严格为零，整个系统与原始 DiT4DiT 完全一致；训练后模型再逐渐学会需要加多少三维信息。

这一环节的关键约束：三维信息必须先进入 Cosmos 视频表征，不能另开捷径直接送给 Action DiT。这保证我们验证的是“3D → 视频表征 → 动作”主线。
04

形成“加入三维信息后”的视频隐藏表征

视频隐藏表征不是一张可视化图片，而是 Cosmos 内部的一串时空特征向量。每个向量对应某个时间、某块画面以及大量抽象语义。

原始视频表征

只由 RGB、语言等原始 WAM 输入形成，记作“加入三维前的特征”。

三维修正量

对象特征经过空间交叉注意力后产生的残差，表示三维信息具体改变了哪些视频特征。

增强后视频表征

原始视频表征加上三维修正量，再继续经过 Cosmos 后续计算并交给 Action DiT。

加入三维前的视频隐藏表征+三维残差=加入三维后的视频隐藏表征→Cosmos 后续层 / Action DiT

为什么要同时保留“前”和“后”？

两者相减就得到纯粹由三维条件引起的变化。这样可以测量三维模块是否真的在工作，也可以让未来三维探针只分析三维带来的新增信息。

怎样判断不是随便改了一下？

仅仅让特征变化并没有意义。我们还要检查这份变化能否预测未来物体位置、表面点运动和夹爪交互，并比较正确三维、关闭三维和错误位姿三种条件。

当前已经证明：正确三维产生的视频残差包含有用的未来平移、点轨迹和交互信息。在固定验证轨迹上，正确三维显著优于关闭三维和偏移位姿；但旋转预测尚未全面通过。
05

用未来三维变化监督视频表征学到“可行动的几何”

如果只使用动作损失，模型可能完全依赖 RGB、语言和对象编号。未来三维监督的作用，是明确要求视频表征理解对象接下来如何运动，而不是只发生任意数值变化。

探针能看到什么

它只读取目标对象区域内的“三维残差”，即加入三维前后视频特征的差值。

训练答案是什么

从几何伴随文件中读取当前帧与第 t+7 帧的真实物体/夹爪位姿，计算未来变化。

如何回传

预测误差通过视频残差、空间适配器和几何编码器反向传播，迫使注入方向携带可预测的三维动态。

监督项模型要预测什么为什么有用
未来平移目标对象到第 t+7 帧在 x、y、z 三个方向移动了多少。直接对应接近、抬起、搬运和放置等动作产生的空间变化。
未来旋转目标对象相对当前时刻旋转了多少。用于理解转动物体、调整抓取方向等行为；目前这一项仍需改进。
表面点轨迹把当前对象表面点通过未来位姿变换后，预测这些点将去哪里。同时约束平移、旋转和物体尺寸，比只预测中心点更完整。
物体—夹爪交互预测未来物体与夹爪的相对位置关系。把对象运动与机器人运动联系起来，减少只学场景运动统计的可能。
正确/错误条件排序要求正确位姿的预测误差小于人为偏移后的错误位姿。验证模型不仅“用了某些三维数值”，而且在意三维信息是否正确。
防止答案泄漏：第 t+7 帧位姿只用于计算损失，探针的输入里没有未来位姿，也不直接读取当前点云或位姿；它必须从已经改变的视频表征中解码答案。
06

Action DiT 读取增强后的视频表征并生成连续动作

这是最终目标环节：不是证明视频特征“懂三维”就结束，而是要让这种表征真正帮助机器人动作预测。

输入

加入三维信息后的 Cosmos 视频隐藏表征，以及数据中可用的机器人自身状态。

训练目标

专家示范中的一段连续动作。每个动作通常包含三维平移、三维旋转和一维夹爪开合，共 7 个维度。

输出

不是只预测下一步，而是生成一个动作片段，使机械臂连续执行接近、抓取、搬运或放置。

增强后视频表征+带噪动作片段+扩散时间步→Action DiT→逐渐去噪→连续动作片段

动作扩散模型在学什么？

训练时给专家动作加入随机噪声，让 Action DiT 根据视频表征和扩散时间步恢复正确动作。推理时从随机动作开始多次去噪，最终得到可执行动作片段。

正确与错误三维如何公平比较？

同一帧、同一专家动作分别输入正确三维、关闭三维或偏移位姿。比较时固定扩散噪声、时间步和随机失活状态，尽量确保损失差异只来自三维条件。

为什么还要拆分动作损失？

总动作损失混合了位置、旋转和夹爪开合。三维信息可能只改善位置控制，却被其他维度的波动淹没，因此下一步要分别评估平移、旋转和夹爪误差。

为什么当前动作验证还没通过？

同一张 RGB 和同一句语言本身已经能提示动作；人为改错三维后仍沿用原专家动作，并没有真实的“错误场景应当采取什么动作”标签，所以 Action DiT 可以选择忽略三维，继续依赖视觉和语言捷径。

当前结论：这一环节只观察到微弱的“正确位姿优于错误位姿”信号，统计上还不稳定；正确三维也没有稳定优于完全关闭三维。因此目前只能说三维信息已经进入并改善视频表征，不能说它已经改善动作或闭环成功率。

03 · 实验过程

实验是如何一步步收敛的

每次负结果都用于排除一个解释，并推动下一次结构或数据修正。

V1 · ACTION ONLY

简单点云编码 + action loss

wrong shape 与 correct shape 没有稳定排序。排除“接线完全不通”后，发现 ID / confidence shortcut 和 action-only 监督过于间接。

V2 · POINT QUERIES

无序点集编码与初始化修正

改善 shape token 可分性，point branch 有真实梯度，但 action gate 仍失败，说明瓶颈不只在 encoder。

PRETRAINED 3D

Point-MAE + 共享度量坐标系

引入冻结预训练 3D encoder、EEF-relative pose 与 metric scaling，使“3D prior”从单一 embedding 扩展为形状、坐标系和动态监督。

FUTURE 3D GATE

受控解冻首次证明 video hidden 有用

正确 3D 在 held-out future translation / point trajectory 上显著优于 disabled 与 offset pose，主表征链路通过。

ACTION BRIDGE

当前单帧同时监督 future 3D 与 action

future-3D 能力显著保持；action 对错误位姿出现微弱敏感，但 geometry presence 尚未显著改善 action。

RESIDUAL TOKEN

目标区域均值摘要没有解决 action gate

显式追加 video residual summary 后，full 仍不优于 disabled，并丢失弱 pose-correctness 信号。由此排除“只因局部 token 被稀释”的简单解释。

05 · 当前问题

当前真正的问题在哪里

问题已经从“工程链路是否工作”收缩为“什么数据与目标能让 action 必须使用 3D”。

科学问题：action supervision 可辨识性不足

同一 RGB、语言和动作标签下人为扰动 geometry，并没有与之对应的真实 counterfactual action 标签。模型可以忽略 3D；scalar diffusion loss 又混合 xyz、旋转和夹爪，使局部 metric 收益更难被观察。继续堆 adapter 或增大 margin 并不能自动解决这一点。

数据问题：shortcut 仍然存在

固定 object ID↔mesh、任务文本和 RGB 可泄露 object / action 信息。需要更强的跨 pose、跨对象但操作语义匹配的数据，或聚焦接近、抓取、放置等真正 geometry-sensitive 帧。

表征边界：旋转尚未通过

当前可靠收益集中在 translation 与 point trajectory。rotation 的 full-vs-disabled 仍可能更差，不能把结果包装为完整 SE(3) dynamics 已解决。

临时工程阻塞：服务器 GPU device nodes

断电重启后 PCI 与 NVIDIA 580.178.04 kernel modules 均可见，但 /dev/nvidia* 未生成，导致 nvidia-smi 失败。这是服务器驱动/udev 初始化问题，不是项目代码或 checkpoint 损坏。

C1 · 路线关系

原始构想保留什么，调整什么

总问题没有改变：3D 必须帮助动作，而不能只改变内部特征。改变的是达到这一目标的中间机制。

原始 WAM-3D

静态 3D → video hidden → action

对象点云、位姿与空间 mask 被编码后注入 Cosmos/video representation，再由 Action DiT 间接读取。

  • 已证明 3D 能进入并改变 video hidden。
  • 已证明 residual 可解码部分未来几何。
  • 尚未证明 action 或闭环成功率提高。
→
调整后的 WAM+3D

候选动作 → 3D 后果 → 动作选择

把候选动作展开为部署时可获得的机器人三维轨迹，显式预测场景轨迹，并用预测结果重排候选。

  • 3D 从附加条件变成物理后果预测变量。
  • 同状态反事实分支直接监督动作差异。
  • 通过后再把动态 3D tokens 接回 Action DiT。
研究边界：如果最终只保留外挂 reranker，项目将更准确地称为“3D causal verifier for WAM”；如果 gate 通过后把动态 3D prior 接回 Action DiT/shared latent，则仍是原 WAM+3D 构想的因果化升级。
C2 · 总体架构

先生成候选，再预测物理后果，最后选择动作

第一版保持模块化：不重训 Cosmos，不立刻改 Action DiT，用最小成本回答动态 3D 是否真的具有决策价值。

01 · OBSERVE当前 RGB-D / 3D scene对象或场景点、世界坐标、语言目标与机器人当前状态。
02 · PROPOSEDiT4DiT 生成 K 个动作片段保留现有 WAM 的动作先验与生成能力，不从头训练大模型。
03 · REALIZENominal robot point flow只由当前状态、候选命令、控制器和运动学得到；不读取接触后的未来状态。
04 · PREDICT轻量 3D causal dynamics输入当前三维和候选机器人轨迹，预测完整物体/场景 point trajectories。
05 · SCORE目标与物理可行性评分依据任务进展、接触、碰撞、终点、不确定性对候选排序。
06 · EXECUTE选择动作并闭环执行执行 top-1 chunk；最终以 LIBERO success rate 判断是否真正有用。
关键接口

F̂ᵢ = Dynamics(Sₜ, Aᵢⁿᵒᵐⁱⁿᵃˡ)：对每个候选独立预测场景轨迹，因此训练时可以使用 expert/candidate 配对，推理时不需要知道 expert。

禁止输入：执行候选后实测得到的未来 EEF trajectory。它只作为 realized-flow oracle，用来测量信息泄漏和性能上限。

C3 · 数据接口

Schema v3：统一世界坐标与物理时间

动作和场景变化都表示成有点身份、有时间戳的三维轨迹；当前阶段先聚焦夹爪与任务对象，避免静态背景稀释信号。

字段来源与形状用途与限制
scene_points_world当前对象/场景点，[N, 3]模型可见的当前三维状态；必须使用统一米制世界坐标。

nominal_robot_flow当前 robot state + controller/kinematics，[M, H, 3]正式动作条件；部署时必须可以在执行前获得。

C4 · 训练目标

绝对轨迹是辅助，动作造成的差异才是主监督

核心设计是同一个初始状态下比较多个动作，阻止模型只根据场景猜测平均终点。

完整轨迹损失

L_traj = Huber(F̂ᵢ, Fᵢ)

监督所有物理时刻的 point flow；分别统计 Moving ADE、Moving FDE 与 Static ADE。

反事实差分损失 · 核心

L_pair = Huber((F̂ᵢ−F̂ⱼ), (Fᵢ−Fⱼ))

同状态 candidate-vs-expert 或 candidate-vs-candidate 配对，直接学习“换动作会改变什么”。

方向与幅度

L_effect = L_cos + λ · L_magnitude

只对真实 effect 足够大的动态分支计算方向，避免静止样本让 cosine 失真。

物理正则

L_phys = L_static + L_contact + L_uncertainty

限制静态漂移，强化接触阶段，并显式输出预测不确定性供 reranker 使用。

总目标

L = L_pair + λ₁L_traj + λ₂L_effect + λ₃L_phys

第一轮仍使用小模型和现有 63 个训练 states 做机制验证，不扩展成大规模视频生成器。只有因果 gate 出现可靠正信号后才增加数据和模型容量。

C6 · 贡献定位

贡献不在“用了 3D”，而在 3D 如何改变决策

可能贡献与近期工作的区别成立条件
已有 WAM 的外挂式 3D causal prior不从头训练 1B 级 3D-native WAM；保留 DiT4DiT，低成本校验候选。显著提高 ranking 或闭环成功率。
同状态 paired intervention supervision不只拟合单条 rollout；直接约束候选动作后果之差。优于相同模型的 absolute-only loss。
Nominal / realized action-flow 分离明确排除未来机器人状态泄漏，并给出 oracle 上限。nominal-flow 模型在 locked test 上仍有效。
Prediction → ranking → execution 证据链不以 auxiliary loss 或视觉质量代替动作有效性。完整通过 G1、G2、G3。
当前状态：这些是已经固定的贡献假设，不是已经成立的论文结论。如果只改善 EPE 而没有改善 intervention、ranking 和闭环成功率，就不能宣称方法贡献成立。

“停止路线”到底停止什么

停止：继续把当前逐样本 absolute endpoint checkpoint 接入 Cosmos/Action DiT，或通过增加训练步数、调权重把它包装成成功。
不停止：WAM+3D 总项目、counterfactual rollout 数据、三维轨迹监督和让 3D 真正帮助动作的目标。若 nominal + paired intervention 仍不能通过 G1，才停止显式 point-flow forward model 这一分支，转向 joint world-action latent 或 3D contact/affordance scorer。
